Promise Mechanics – Core Rules (Phase 1)

  • Promise constructor runs synchronously
    The executor function inside new Promise() runs immediately, not asynchronously.
  • .then(), .catch(), .finally() callbacks are always asynchronous
    They are placed in the microtask queue, even if the promise is already resolved.
  • .then() return rules control the chain
    • Returning a value → next .then() receives it
    • Returning a promise → chain waits and unwraps it
    • Throwing an error → converts to a rejected promise
  • Errors bubble down the promise chain
    Once a promise is rejected, all following .then() calls are skipped until a .catch() is found.
  • .catch() is equivalent to .then(undefined, onRejected)
    It only catches errors from previous promises, not future ones. Placement matters.
  • .finally() is for cleanup only
    • Receives no value or error
    • Cannot modify the resolved value
    • Runs on both resolve and reject
    • Only throwing inside finally() affects the chain
